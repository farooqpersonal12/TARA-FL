3. THE BASIC PROBLEM
Imagine 20 phones/laptops/hospitals have private data.
We want to train one AI model using data from all of them.
But we don't want this:

Client 2 ──┤
Client 3 ──┤

...        │
Client 20 ─┘
Raw private data → Server

financial information
personal information
user activity
private images
etc.

8. WHY IS IT CALLED "DYNAMIC" TRUST?
Trust is not fixed.
Example:
Round 1
Client 5 → Trust = 0.30
It behaves well.
Round 2
Client 5 → Trust = 0.50
Again good.
Round 3
Client 5 → Trust = 0.70
It may now be considered more trustworthy.
But another client could behave badly:
Round 1 → 0.90
Round 2 → 0.80
Round 3 → 0.45
Round 4 → 0.18
So trust changes according to behavior .
9. BUT WE ARE NOT SIMPLY BUILDING "HIGH
TRUST = SELECT"
This is an important difference.

=== PAGE 7 ===
A basic trust-based project would do:
High trust → Select
Low trust → Reject
We want to investigate something more flexible.
TARA-FL can divide clients into trust levels.
High trust
0.75 – 1.00

Medium trust
0.40 – 0.74
→ reduced influence or additional checking
Low trust
0.00 – 0.39
→ verification, reduced influence, or quarantine
These thresholds are examples and are NOT finalized yet.

18. WHAT MAKES OUR PROJECT DIFFERENT?

"Trust-based FL is new."

32. THE PROJECT IN ONE SIMPLE EXPLANATION
If someone asks:
“Bro, what are we actually doing?”

clients. It continuously evaluates client behavior and assigns trust scores. Instead of
simply removing every low-trust client, the system can reduce their influence or send
suspicious clients for verification. The server also evaluates the risk of the current
training round and can adapt the aggregation strategy accordingly. We will compare
